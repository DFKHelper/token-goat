PART 2 How and when the semantic index triggers, and what is indexed

The index runs automatically in the background in your local development environment whenever files are saved or modified, just like VS Code's local search index. It does not send your code to any cloud API; it uses a small local model (bge-small-en-v1.5, ~30 MB).

  • What is indexed: Function signatures, class definitions, method bodies, type declarations, docstrings, and markdown docs across 27+ languages.
  • What is strictly ignored: Your node_modules/ folder, build output folders (dist/, target/), compiled binaries, and .git internals.

In a long session (like fixing a tricky bug or refactoring an API), the agent carries every previous turn in its memory. Every time an agent reads a file, that entire file stays in context on every single subsequent turn, compounding session size exponentially.

PART 2 Doesn't enterprise prompt caching make repeated tokens cheap or free?

This is the most common counter-argument from engineers familiar with Anthropic or OpenAI prompt caching. On paper, cached prompt tokens receive up to a 90% discount. In production engineering workflows, prompt caching does not eliminate the penalty of context bloat for five concrete reasons:

  1. The 5-Minute Eviction TTL (Developer Thinking Time): Provider prompt caches (Anthropic Ephemeral Cache, OpenAI Prompt Cache) have a strict 5-minute time-to-live (TTL). Real engineering work is not an automated batch script. You stop to review a git diff, inspect a compiler error, run a local debugger, test an endpoint in Postman, or think through a design choice. The moment you pause for more than 5 minutes between turns, the cache is completely evicted. On your next turn, you pay 100% full price (actually 125% on Anthropic due to cache-write pricing) to write all 85,000 tokens back into GPU memory. In a realistic 10-turn debugging session, developers bust the 5-minute cache window 4 to 6 times.
  2. Prefix Invalidation (The Branch & Edit Trap): Prompt caching is strictly a prefix cache: every token from token 1 down to the checkpoint must match byte-for-byte. The moment you edit a file, run a tool that returns a varying timestamp or process ID, or switch git branches, the cache invalidates downstream and every token is billed at full cost.
  3. Context Window Ceilings & Lossy Auto-Compaction: A 90% billing discount does not expand the physical context window. When an agent fills 150,000 tokens with full-file dumps, you hit the context limit. The harness triggers aggressive, lossy auto-compaction (dropping earlier turns, forgetting constraints, and losing instructions). Organizational rate limits (Tokens Per Minute, or TPM) also measure total token volume regardless of cache status. An agent pushing 85,000 tokens per turn rapidly triggers 429 Rate Limit Exceeded errors across your team.
  4. Attention Dilution ("Lost in the Middle"): Transformers are not relational databases with index pointers. When an LLM evaluates code across 85,000 tokens of mostly irrelevant CSS, boilerplate imports, and unrelated methods, self-attention is diluted. Needle-in-a-haystack retrieval degrades, causing the model to miss edge cases, forget constraints, or hallucinate bugs. Keeping context lean (11,500 tokens) delivers measurably higher code accuracy than bloated context (85,000 tokens), even if those extra tokens were zero dollars.
  5. Prefill Latency (Wait Time): Even on warm cache hits, processing an 85,000-token prompt adds 3 to 6 seconds of prefill latency. On cold turns after a 5-minute pause, prefill can take 12 to 15 seconds before the first token streams. A surgical 11,500-token session responds in under 2 seconds.

When the agent attempts to read a 2,500-line file, token-goat intercepts the call and serves only the 30-line function needed.

VS Code helps the model find the file; token-goat prevents that file from flooding your context window.

No. Token-goat produces massive net savings on both system resources and token costs:

  1. Tiny local footprint: Token-goat runs locally as an embedded SQLite WAL database consuming under 40 MB of RAM. Hook checks execute in-process in 5 to 15 milliseconds, which is imperceptible compared to a 2,000-millisecond API round-trip.
  2. Massive token ROI on first read: The moment Copilot or any agent reads a file, token-goat cuts prompt consumption by up to 98% (e.g. 130 tokens instead of 11,000 tokens), paying for its background index many times over on the very first turn.
  3. Protects what VS Code ignores: VS Code's index does not deduplicate re-reads of unchanged files, does not fold noisy terminal command output (like 500 lines of passing tests), does not slice PDFs or spreadsheets, and does not operate outside VS Code (such as in Claude Code, Copilot CLI, Codex, or Cursor). This is the most common counter-argument from engineers familiar with Anthropic or OpenAI prompt caching. On paper, cached prompt tokens receive up to a 90% discount. In production engineering workflows, prompt caching does not eliminate the penalty of context bloat for five concrete reasons:

  2. Prefix Invalidation (The Branch & Edit Trap): Prompt caching is strictly a prefix cache: every token from token 1 down to the checkpoint must match byte-for-byte.   3. Context Window Ceilings & Lossy Auto-Compaction: A 90% billing discount does not expand the physical context window. When an agent fills 150,000 tokens with full-file dumps, you hit the context limit. The harness triggers aggressive, lossy auto-compaction (dropping earlier turns, forgetting constraints, and losing instructions). Organizational rate limits (Tokens Per Minute, or TPM) also measure total token volume regardless of cache status. An agent pushing 85,000 tokens per turn rapidly triggers 429 Rate Limit Exceeded errors across your team.
  4. Attention Dilution ("Lost in the Middle"): Transformers are not relational databases with index pointers. When an LLM evaluates code across 85,000 tokens of mostly irrelevant CSS, boilerplate imports, and unrelated methods, self-attention is diluted. Needle-in-a-haystack retrieval degrades, causing the model to miss edge cases, forget constraints, or hallucinate bugs. Keeping context lean (11,500 tokens) delivers measurably higher code accuracy than bloated context (85,000 tokens), even if those extra tokens were zero dollars.
  5. Prefill Latency (Wait Time): Even on warm cache hits, processing an 85,000-token prompt adds 3 to 6 seconds of prefill latency. On cold turns after a 5-minute pause, prefill can take 12 to 15 seconds before the first token streams. A surgical 11,500-token session responds in under 2 seconds.

The Transformer Mechanics: Why Token-Goat Produces Measurably Better Code
1. Attention Focus vs. Attention Dispersion:
Transformers compute pairwise self-attention across every token in the prompt ($O(N^2)$ dot-product operations). When a prompt contains 4,000 lines of irrelevant imports, CSS, and unrelated methods, attention weights disperse across distractor tokens. By supplying only the targeted method AST and its interfaces, virtually 100% of the model's self-attention heads focus directly on the target algorithm and variable types.

2. Physical Bounding of the Diff Surface:
When an agent reads an entire 1,400-line class to modify a 10-line calculation, the edit tool must rewrite or replace sections across the whole file. Models frequently reformat tabs, alter comments in adjacent functions, or drop decorators. When Token-Goat serves only PricingEngine.ts::calculateTierDiscount, the model's edit is physically bounded to that single method. Diff sprawl drops to near zero.

3. Preventing "Lost in the Middle" Instruction Eviction:
In extended debugging workflows without Token-Goat, token accumulation forces earlier instructions into the middle of the context window. As demonstrated by Stanford research and the Needle In A Haystack test suite, retrieval accuracy degrades sharply in the middle third of large contexts. Keeping context under 5,000 tokens ensures system prompts, architecture constraints, and edge-case requirements remain in pristine, high-attention working memory.
